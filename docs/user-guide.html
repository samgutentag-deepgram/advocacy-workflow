The advocacy workflow

Every command, every file, every Asana action, from an empty folder to a finished campaign. Written to be followed by someone who has never run any of it.

Read this first Three skills do the work and they run in a fixed order: project-hub sets the project up, advocacy-intake decides it is worth content, advocacy-cycle produces the content. Nothing skips ahead. Each one refuses to run if the one before it has not.

Before you start

Do all of this once, per machine.

# 1. Install both plugins, inside Claude Code. project-workflow first: every skill here needs it.
claude
/plugin marketplace add samgutentag-deepgram/project-workflow
/plugin install project-workflow@project-workflow
/plugin marketplace add samgutentag-deepgram/advocacy-workflow
/plugin install advocacy-workflow@advocacy-workflow

# 2. Video rendering only. Skip if you are not making videos.
brew install uv ffmpeg
export DEEPGRAM_API_KEY=...                  # or put it in a .env file

You also need the Asana connector enabled in Claude Code. Check it before you start: ask Claude "list my Asana workspaces". If it cannot, stop and connect it. Every stage after the first writes to Asana.

The first-run interview

The first time you run any advocacy command, it checks ~/.claude/advocacy-workflow.yml. If anything is missing it interviews you, writes the file, then carries on with whatever you originally asked. It never asks about a field that is already filled.

To see where you stand at any time:

PLUGIN=$(ls -d ~/.claude/plugins/cache/advocacy-workflow/advocacy-workflow/*/ | tail -1)
python3 "$PLUGIN/skills/advocacy-intake/scripts/config.py" --missing
python3 "$PLUGIN/skills/advocacy-intake/scripts/config.py" --show
python3 "$PLUGIN/skills/advocacy-intake/scripts/config.py" --path

--missing exits non-zero while anything is unanswered, so you can gate a script on it. Four settings, one of which is a fact about your Asana workspace:

SettingWhere the answer comes from
asana_workspaceAsk Claude to list your Asana workspaces
lab_rootDefaults to ~/LABS
voice_personalDefaults to personal-style
voice_corporateDefaults to corporate-style

The file is one person's setup on one machine, reused by every campaign. Safe to edit by hand.

The lab repo convention

Every campaign runs inside a lab repo: a private working repo named <thing>-lab, kept under lab_root. The -lab suffix is the whole point. A repo without it is one you might publish by accident, and these repos hold unpublished drafts and a build ledger that should never ship. The clean public repo is created separately at the very end, and the lab repo never becomes it.

Your own writing voice

personal-style and corporate-style ship with the plugin and are written to work for anyone. If you have your own voice skill, name it in voice_personal and it is used instead. That field is also how you ghostwrite: point it at somebody else's voice skill and the drafts come out in their voice, not yours.

Start a new Claude Code session after running setup.sh. Skills load at session start and will not appear in a session that was already open.

Words you need first

Lab repo
The private working repo, always named <thing>-lab and kept in ~/LABS/. It never goes public. A separate clean repo is published at the end.
Hub
The .hub/ directory in a lab repo. Holds index.html (the page you open), hub.yml (config and the Asana link), ledger.md, and assets/.
Ledger
.hub/ledger.md. An append-only record of what happened while building: dead ends, symptoms before you knew the cause, alternatives that lost. Every later claim traces back to it. It cannot be backfilled.
Capture plan
.hub/capture-plan.md. What you intend to film or screenshot. Filled in before the project first works, because that moment happens once.
Surface
One place content gets published. There are seven, across two branches. A surface is either a blog or a derivative.
Branch
personal or corporate. Peers, same length. Only difference: video comes off the personal blog only.
Canonical
The one version of a piece that you review properly. Everything else derives from it.
Variant
A canonical rewritten in one of the four styles. Used to repost the same material weeks apart. A variant changes framing, never a claim.
Style
One of technical, build-it-too, fun, user-demo. Defined in the plugin's skills/script-to-video/styles/. All four are used on every canonical, every time.
Gate
A review checkpoint, A through D. You pass a gate by completing its task in Asana. Nothing downstream is written until you do.
Beat
An inline HTML comment inside a draft that scaffolds one section: its name, word budget, the job it does, and the facts it may use. You write into it and delete it when the section lands. Beats still in a file are sections still unwritten.
advocacy.md
advocacy/advocacy.md. The frozen claim, the reader, and the surfaces. Written once by advocacy-intake. Never edited afterwards.
notes.md
advocacy/notes.md. Every verified fact with a citation. The only source drafts may project from. If it is not in here or in a cited source, it does not ship.
Base layer
A placeholder video with a synthetic voice, produced by script-to-video. It exists to fix timing and structure. You re-record it with your own voice and screens.
Day 0
The date the campaign counts from. Asked once, at promotion. Everything is dated day 0 plus an offset, and the project runs to day 0 plus 90.
Prep spine
The four setup tasks filed at promotion: clear the publishing gate, add a LICENSE, verify every number, record the campaign footage. Which ones appear depends on the repo.

The whole run at a glance

The run, stage by stage

1. Create the lab repo

mkdir ~/LABS/thing-lab && cd $_
git init
claude
You doBuild. Commit as you go. Keep going until there is real code to read.
OutputA git repo with files in it.

The -lab suffix is not optional. A repo without it is one you might publish by accident.

2. Create the hub

/init
/project-hub init
NeedsCode in the repo. /init reads it, so it must exist first.
AsksWhen should this be working or dropped. Default is one week.
Output.hub/index.html, .hub/hub.yml, .hub/ledger.md, .hub/assets/, .hub/capture-plan.md, and four exploration tasks in a new Asana project.
Then youBuild. There is nothing to do in Asana by hand.

Safe to re-run. It never touches a ledger or overwrites an authored value.

3. Build, and capture as you go

/project-hub capture
WhenEvery dead end, surprise, or change of mind. The same turn it happens, not at wrap-up.
OutputAn appended entry in .hub/ledger.md.

Fill in .hub/capture-plan.md before the project first works. Tripod up, film the failures too. That moment happens once.

4. Promote it to a campaign

cd ~/LABS/thing-lab && claude
/advocacy-intake
WhenOnce it works and you have decided it is content.
Needs.hub/hub.yml with an asana key. Without it the skill refuses and tells you to run /project-hub init.
AsksWhich surfaces to keep, and what day 0 is. Declining a surface is a real answer.
Outputadvocacy/advocacy.md, written once and frozen.
In AsanaDates set to day 0 through day 0 plus 90, which is what marks the project a campaign, and the prep spine plus gates A and B are filed.

Keeping a derivative without its branch's blog is refused. A thread has nothing to derive from without its blog.

5. Start the cycle

/advocacy-cycle init
Needsadvocacy/advocacy.md. Refuses without it.
Outputadvocacy/notes.md (every fact, cited, out of the ledger), advocacy/notes.companion.md, and the empty advocacy/content/ tree.
In AsanaGates C and D filed: 5 parent tasks with 4 subtasks each, plus the render batch with 4.
Alsoadvocacy/renders/ added to .gitignore.

6. Gate A, the two blogs

/advocacy-cycle draft personal_blog
/advocacy-cycle draft corporate_blog
Outputcontent/personal/blog.md and content/corporate/blog.md, each full of inline beat comments.
You doEdit until it is publish ready. Delete each beat comment as you finish its section.
To passComplete Gate A: Personal blog, edit to publish ready in Asana. Same for the corporate one.

Important You never edit a status field by hand. The skill reads the board and writes the answer back into the file. Asana is the source of truth.

7. Gate B, the five canonicals

/advocacy-cycle draft personal_thread
/advocacy-cycle draft personal_linkedin
/advocacy-cycle draft personal_video_script
/advocacy-cycle draft corporate_thread
/advocacy-cycle draft corporate_linkedin
NeedsThat branch's Gate A blog task complete. Otherwise the skill stops and names what it is waiting on.
OutputFive files, one per surface, at the top of each surface's directory.
To passComplete each Gate B: <surface>, edit to publish ready task.

8. Gate C, the twenty variants

/advocacy-cycle variants personal_thread
/advocacy-cycle variants personal_linkedin
/advocacy-cycle variants personal_video_script
/advocacy-cycle variants corporate_thread
/advocacy-cycle variants corporate_linkedin
NeedsThat canonical's Gate B task complete.
OutputFour files per surface in variants/, one per style. Twenty total.
You doA light pass. These are staggered reposts of approved material.
To passComplete each Gate C: <surface>, <style> variant subtask.

9. Gate D, the four videos

/advocacy-cycle render
NeedsThe four personal_video_script variants approved, and DEEPGRAM_API_KEY set.
OutputFour horizontal mp4s in advocacy/renders/, beside the JSON that produced them. Gitignored.
You doWatch them. Keep the framing that works. Re-record with your own voice and screens.
To passComplete the Gate D subtasks.

A failed take does not stop the batch. The rest render, failures are listed at the end with a retry command, and the exit code is non-zero. Check the summary rather than assuming a clean run.

10. Check everything

/advocacy-cycle check
RunsFive checks: citations, facts, limits, links, beats.
OutputA list of findings with the file and location of each. An empty list is a pass.

Run this before you publish anything. citations resolves every file.py:120-140 reference against the repo, which is what stops you filming code that has moved.

11. Ship each piece

/advocacy-cycle ship personal_blog
You doPublish the piece yourself, then give the skill the live URL.
Outputpublished: set in that file's frontmatter, and the file synced from the live page.

Once a piece is live, the site is the source of truth for its own copy. The repo file gets updated from the published page, never the other way round.

12. The public flip

gh repo create thing --public
BeforeDecide the chapters. Rewrite history to build order. Strip .hub/ and advocacy/ from every commit, not just the tip.
CheckInspect the tree for .hub before you push, not after.
AfterThe lab repo is finished. Keep it forever, never work in it again except to write content from its ledger.

One way only. The lab repo never goes public and the public repo never comes back. Pull requests on the public repo are applied by hand, there.

Good to know

Is it safe to re-run anything? Yes. Every skill here is idempotent. They create only what is missing and never delete a task or overwrite an authored file.

A skill refused to run. What now? Read the message; it names what to run first. The three most common: no .hub/hub.yml asana key means run /project-hub init; no advocacy/advocacy.md means run /advocacy-intake; a parent not approved means complete that gate task in Asana.

Where do I mark something approved? In Asana, by completing the gate task. Never by editing a file. The status: line in frontmatter is a cache the skill writes; if you edit it, it is overwritten on the next sync.

What if Asana is down? The cycle falls back to the cached status: and tells you it is reading a cache and how old status_synced: is. Treat that as a warning, not a normal run.

I forgot to keep a ledger. Can I backfill it? No. Code, numbers and screenshots are recoverable later; what it was like on the day is gone by tomorrow. Accept it, note that the build-log post will be weaker, and capture from today.

Can I skip a surface? Yes, at promotion. Declining is a real answer. The one rule is that you cannot keep a derivative without its branch's blog.

Can I use only one style instead of four? No. All four, on every canonical, every time. The variants exist to fill gaps between campaigns.

Do the videos ship as-is? No. They are placeholders with a synthetic voice, built to fix timing and structure. You re-record them.

What gets committed? Everything under advocacy/ except renders/. Strip the whole directory, and .hub/, before any public flip.
