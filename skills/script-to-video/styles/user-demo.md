# User demo

## Stance
A person who will never read the code is deciding whether to use this. Show the product.

## Leads with
What it is in one sentence, then play it. Get to the artifact faster than any other style.

## Emphasize
- The thing itself running. Long holds while it plays.
- What the user gets: transcripts, chapters, subscribe, back catalog.
- Honest limits, stated as facts rather than apologies.

## Cut
Almost all internals. No file paths, no line numbers, no API parameters.

## Register
Plain, second person, no engineering vocabulary.

## Length
**Naturally the shortest, and let it be.** Padding a product demo to match an engineering
walkthrough is how it stops being a product demo. Buy runtime with holds where the artifact
plays, not with more narration.

## Calibration line
> It is not a summary of a thread. It is the thread, read by two people.
